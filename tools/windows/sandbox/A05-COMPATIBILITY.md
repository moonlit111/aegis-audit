# A05 Windows fuzzing compatibility

Current compatibility evidence is generated by
`scripts/check_windows_fuzz.py`. The latest batch is
`.data/verification/windows-fuzz/a05-compatibility-20260909/summary.json`.

Observed on 2026-09-09:

- MSVC `cl.exe` accepts `/fsanitize=address` and `/fsanitize=fuzzer`.
- Both probes fail at link time because
  `clang_rt.asan_static_runtime_thunk-x86_64.lib` is unavailable.
- Pinned LLVM 23.1.1 is installed as a minimal runtime by
  `install-llvm.py`.
- LLVM libFuzzer and libFuzzer+ASan probes compile and run on the host.
- A prebuilt libFuzzer probe also ran in Windows Sandbox and reported
  inline-8-bit-counter coverage.
- Source coverage-guided fuzzing is therefore `READY` as an engine experiment;
  product integration and in-guest compilation are still pending.
- WinAFL, AFL++, TinyInst, and Jackalope are not installed.
- TinyInst `litecov` built successfully and ran the benign PE64 fixture.
- TinyInst also ran in Windows Sandbox and produced coverage offsets.
- TinyInst is pinned to commit
  `9b564702c01481825e4a1629d1701cf49d3d091f` and installed by
  `install-tinyinst.py`.
- A benign libFuzzer crash fixture now:
  - runs 100,000 fuzz cases in Windows Sandbox;
  - preserves the crash input as `crash-input.bin`;
  - archives the corpus as `corpus.zip`;
  - replays the crash input and reproduces the same nonzero exit;
  - records inline-8-bit-counter coverage.
- Closed-source PE engine status is `READY` as an experiment.
- A05 is now `ENGINE_EXPERIMENT_READY`, not product-integrated.

Next A05 actions are product integration, in-guest engine compilation for
libFuzzer, crash deduplication, minimization, and repeated replay evidence.
