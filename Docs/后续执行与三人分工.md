1. 不重复安装全部开发工具；先用现有私有工具和预检查定位缺项。

5. 不把 Job Object 当成安全沙箱；它只解决进程监督及资源/生命周期问题。
6. 不将旧 Docker 动态测试改个标题写成 Windows 通过；旧 ELF/AFLPP 配置需要显式迁移或拒绝。
7. 不从旧 HEAD 新建三个工作区后直接开工，否则会漏掉所有未提交 Windows 改动。
8. 不执行全仓库恢复、强制重置或全局结束同名进程，不覆盖他人未提交内容。

### 3.1 工作区、服务与算力

- 默认在当前工作区按文件所有权协作；同一文件只允许一个会话处于编辑状态。跨职责修改先发送“文件、目的、字段/函数、测试”给主写人。
- 需要独立目录时，先用包含未提交文件的源码快照建立相同基线。仅执行 git worktree add 指向旧 HEAD 不合格。是否形成新的 Git 提交由集成人审核，不在本次计划整理时替用户提交。
- 同一台机器的 .data/server、.data/executor、端口、日志和 Sandbox 任务目录不得混用。C 管集成服务；A/B 用各自独立测试数据或预约集成窗口。
- 不能只换端口就认为数据隔离完成。需要按现有启动参数配置独立数据目录；参数不支持时先补测试启动器，不能指向同一 SQLite 数据库。
- 当前已有服务不能被其他人用 manage.py stop 随意停止。重建和重启前核实当前任务，长任务观察超时不等于进程已结束。
- 初始仅允许一项 Sandbox 动态任务；Rust Release、Ghidra 大任务、模糊测试和大型模型目标不要同时满载。C 记录资源窗口，A 设置动态并发上限。
- 每人完成一个小任务就交付差异、测试、证据及剩余问题，不积累到最后一次性合并。
