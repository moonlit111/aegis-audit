## 3. 阶段划分：按文件规模分批（不是按漏洞类别）

实测目标文件规模差 34 倍，而审计按"程序单元（模块+函数）"逐个做、受 `max_units` 限制。**若 `max_units` 小于文件单元数，Planner 可能把目标函数排在预算之外，结果是"未覆盖"而不是"没能力检出"**——必须按规模分档，否则会自欺。

| 阶段 | 规模档 | 对数 | 明细（行数 / 函数数） | 建议 `max_units` |
| --- | --- | --- | --- | --- |
| 1 | 小文件 ≤200 行 | 4 | #4 `history.go` 155/9、#8 `auth.go` 105/4、#9 `image.go` 179/9、#3 `gradio_patch.py` 167/6 | 20（可全覆盖） |
| 2 | 中文件 200–1300 行 | 3 | #6 `download.go` 499/18、#5 `server.go` 1108/16、#7 `images.go` 1279/29 | 40 |
| 3 | 大文件 >1300 行 | 2 | #2 `llama.py` 1719/60、#1 `llama_chat_format.py` 3581/82 | 100（成本高，可降为"接受部分覆盖并如实记录"） |

阶段 1 恰好覆盖四类里的三类（**INJECTION** #3、**AUTHORIZATION** #4/#8、**MEMORY_BOUNDS** #9），PATH_TRAVERSAL 在阶段 2（#7）。所以阶段 1 就能给出"四类中三类有结论"的最小可用结果。

## 4. 每对的输入构造：范围钉死（做法 A 优先）

```bash
# 有洞包
git -C .data/security-pool/repos/<clone> show <vulnerable_rev>:<file> > <tmp>/vuln/(原相对路径)
# 修复包
git -C .data/security-pool/repos/<clone> show <fixed_rev>:<file>   > <tmp>/fixed/(原相对路径)
```

- 两包**同路径、同文件名**，ZIP 内保留原始相对路径，否则对照不成立。
- 做法 B（仅当解析或语义需要同目录依赖时）：加最小的同目录文件，**必须记录加了哪些**，并说明是否影响引文范围。
- 两包使用**完全相同的运行配置**。

## 5. 判定口径：四分列，不许合并

| 记号 | 条件 |
| --- | --- |
| **命中** | 存在 finding：`category` 等于该对预期类别 **且** `reviewStatus == VALIDATED` **且** 引文覆盖目标文件 |
| **有候选未成立** | 有 finding 但非 VALIDATED（如 INCONCLUSIVE）——**不算命中**，但要单独统计并摘录 counter_evidence |
| **未检出** | 已审计覆盖但零 finding |
| **未覆盖** | 目标文件/函数不在 `audited_unit_ids` 内——**不算"安全"** |

- **PASS = 有洞包命中 且 修复包零命中**；任一不满足记 FAIL，保留原始 JSON，不重跑掩盖。
- `COMPLETED` 只表示任务结束，**不代表目标安全**。

## 6. 预算与硬停止

- 先跑最省的配置；只在"未覆盖"时提高 `maxUnits`，**不因"没检出"而加预算重跑**（那是掩盖结果）。
- 单对超时或超 `maxModelCalls` → 显式 `CancelRun`，记录为未完成，不计 PASS。
- 每对记录 `model_calls` 数与 token；**用量未知不许记 0**。
- 预计成本：阶段 1 约 8 次审计（4 对 × 2 包），每次 10–20 个单元；阶段 3 单次可达 90 个单元，是本轮最贵的部分。

## 7. 预计的失败模式与对策（先写清楚，避免自欺）

| 失败模式 | 现象 | 对策 |
| --- | --- | --- |
| 未覆盖 | 目标函数不在 `audited_unit_ids` | 提高 `maxUnits` 到覆盖全部单元；仍不覆盖则如实记为"未覆盖"，不算没检出 |
| 有候选未成立 | finding 有但 INCONCLUSIVE | **这是有价值的结果**：记录 `counter_evidence` / `missing_information`，不要重跑到"成立" |
| 修复包也命中 | 修复版仍被判有洞 | 分两种：修复本身不彻底（#2 就是，8→16 未做真正长度查询）或误报；**单独归类，不得算作检出能力** |
| 引文被拒 | 模型引文与原始代码不符 | 服务端会拒绝并回贴真实代码；出现即记为提示词/模型问题，统计发生次数 |
| 权限/配置类被忽略 | 如 #4 的 `0o666` 被当作普通代码 | 预期风险：`AUTHORIZATION` 类别对"文件权限"的敏感度未经检验，这正是本轮要测的 |
