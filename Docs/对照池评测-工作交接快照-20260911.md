### 必须记录的三个系统性发现

1. **权限/umask/TOCTOU 类缺陷在"源码快照即全部输入"下天然无法 VALIDATED**。`ReviewDraft::validate_model` 规定任何必要前提 UNKNOWN 即不得 VALIDATED；模型甚至主动给出反证（"umask=0o077 时风险不成立"）后被规则按住。评测口径需单列一档，否则这类真实缺陷永远计 0。
2. **服务端健壮性缺陷 ×2**（建议报给项目）：
   - `agents.rs` 中 `context.execute("AUDITOR", ...).await?` 直接上抛，**单单元协议校验失败 = 整轮中止**（p03 首轮 0/7 单元、p04 断在 8/10、p06 修复包两轮 PARTIAL）。对比 VERIFIER 循环是显式 catch。错误三类：`missing field audited_unit_ids`、`证据的行范围或引用文本无效`、`invalid type: sequence, expected a str`。
   - REVIEWER 把带 UNKNOWN 前提的候选判 VALIDATED 被 `validate_model` 正确拒绝后，同样整轮中止（p06 修复包重跑）。
3. **运行间方差**：同输入两轮结果可不同（p03 修复包首轮 0 VALIDATED、重跑 2 条）。单轮结果不能下死结论。

export NO_PROXY=localhost,127.0.0.1,::1

  --bootstrap-file <dir>/server/executor-bootstrap.token >> .data/logs/<tag>-executor.log 2>&1 &

**三个必踩过的坑**：
1. `manage.py build` 第三步 `pnpm` 不在 PATH 会失败（`[WinError 2]`）→ 前端要 `npx --yes pnpm@10.33.0 --dir frontend install --frozen-lockfile && ... build` 补；`manage.py start` 硬性要求 `frontend/dist/index.html`。
2. `cd` 和启动服务写进同一个 `&` 会让**整条链进后台**，后续前台命令在错误 CWD 执行。
3. 执行器的 `--bootstrap-file` 默认值是字面量路径、**不跟随 `--data-dir`**，并行实例必须显式传。

**停止**：按 PID `taskkill /PID <pid> /T /F`。查 PID：`tasklist | grep aegis`。主实例的 `manage.py stop` 只对经它启动的生效（`bin/` 当前不存在，本批均为手动启动，需 taskkill）。

**关键能力实测**：`tree-sitter 0.25.10` / `import` / `git` / `string-recovery` / `ida-d810` 可用；**ghidra 与 semgrep 不可用**（semgrep 需 `scripts/bootstrap.py`）。本轮检验的是**语义审计通道**，不是规则引擎——结论里必须写明这一点。

**本地回环必须** `NO_PROXY=localhost,127.0.0.1,::1`，否则模型/服务调用会被系统代理拦截（502）。

## 6. 驱动与判定口径（改动过，按新版为准）

`scripts/check_pair_pool.py`：

- **输入构造**：`git show <rev>:<file>` 打成单文件 ZIP（保留原相对路径）。**必须钉到单文件**——默认 max_units 下整仓会耗尽预算，"没检出"会变成"没机会检出"。
- **四分列**：命中 / 有候选未成立 / 未检出 / 未覆盖；再加一档 **命中改动点**（VALIDATED 证据行 ∩ git diff 改动行 ≠ ∅）。
- **PASS = 漏洞包改动点命中 ≥1 且修复包改动点命中 0**。不要因为"没检出"就加预算重跑；只有"未覆盖"才提高 `max-units`。
- **`--only vuln|fixed`**：协议失败补跑时只跑失败的那个包（另一个包别重复烧钱）。
- **`--structure-only`**：C0 结构自检，不判定漏洞（已特判输出单元清单）。
- **盲测**：不把 CVE 编号 / 公告 / 修复提交信息喂进输入或提示词。

## 7. 离线复判逻辑（写结果文档时直接用）

对每对：`git diff -U0 --no-color --no-textconv <vrev> <frev> -- <file>`，解析 `@@ -a,b +c,d @@` 取行号。旧侧行号 → vuln 包，新侧行号 → fixed 包；**纯新增时取插入点邻域 {a-1, a}**。然后对每包的 `*-audit.json`，取 `reviewStatus == VALIDATED` 的 finding，把证据行集合（`evidence[].startLine..endLine`）与改动行求交集。落在改动点 = "找到了那个缺陷"，否则 = "找到了某个缺陷"。
