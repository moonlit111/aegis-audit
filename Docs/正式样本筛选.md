## 其他核查与选择依据

- [DeepSeek-V3](https://github.com/deepseek-ai/DeepSeek-V3/tree/9b4e9788e4a3a731f7567338ed15d3ec549ce03b) 的官方代码采用 MIT，模型许可独立；README 的原始 671B 推理示例使用 `--nnodes 2 --nproc-per-node 8`。这与本机资源差距明显，因此优先继续核查 DeepSeek-Coder 的软件入口，不能把 V3 源码导入成功当成完整模型服务已运行。
- [Kimi-K2](https://github.com/MoonshotAI/Kimi-K2/tree/1b4022bbb7187cf4011a8bdf0b4cd10e2daa26c4) 为 Moonshot 官方仓库。README 声明代码和权重采用 **Modified MIT**，总参数为 1T；不能省略修改条款或把它写成普通 MIT。保留为来源备选，尚未确定可运行的软件边界及漏洞依据。
- Ollama、llama-cpp-python 和 libwebp 仍仅为开发回归候选，沿用[测试与验收方案](测试与验收方案.md)中的公开公告。公开 CVE 的存在不能替代系统自己的发现与实际验证。

## 调研数据与后续取证

结构测试公开输入位于 [`evaluation/targets/structure-candidates.json`](../evaluation/targets/structure-candidates.json)，只有仓库、提交和正常项目身份。资格与漏洞参考单独存放于 [`evaluation/reference/sample-candidates.json`](../evaluation/reference/sample-candidates.json)，不作为产品分析请求上传。原始网页核查清单及内容 SHA-256 见 [`research-sources.json`](../evaluation/reference/research-sources.json)。

可以用以下命令对上述两个源码候选进行真实导入和结构解析：

```bash
python3 scripts/analyze_candidates.py
```

这个命令不会启动模型、读取漏洞答案或生成利用代码。它产生的源码结构结果属于开发测试；这些项目不能再标为未用于开发的保留集。结果只证明该固定版本的导入和解析行为，不提升 R14 验收计数。

正式录入每个案例前仍需固定：目标发布物与哈希、许可/来源、类别证据、正常运行环境、保护处理链、漏洞答案与产品输入隔离方式。最终成绩依据系统生成的候选、独立复核、输入/利用产物、实际运行日志和目标状态逐项判定。当前没有用调研文字替代这些实验。
