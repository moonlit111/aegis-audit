核心接口使用 Connect RPC；大文件上传/下载可通过 Axum 的 HTTP 路由处理，再用产物标识参与 RPC。协议、领域对象和数据库状态通过明确转换与测试保持一致。

| 接口职责 | 必需行为 |
| --- | --- |
| 项目导入 | 输入目标及可选的正常运行配置，记录哈希、格式/语言识别和解析状态；优先自动识别构建、启动及输入方式，按需请求缺少的信息 |
| 创建/查询任务 | 固定目标、范围、预算和版本，持久化任务状态 |
| 任务进度 | 服务端流传送已记录的事件，客户端可按游标重连和补读 |
| 取消任务 | 显式取消任务并回收相关工具进程；浏览器断线与取消任务分别处理 |
| 模型与工具 | 按职责接收受限上下文，返回结构化结果、真实退出状态、消耗和产物 |
| 漏洞与关键逻辑 | 保存位置、相关代码、调用/分支依据、证据及标注历史 |
| 验证、利用与报告 | 执行证据决定验证状态，报告引用已有事实 |

任务至少区分排队、运行、等待用户补充信息、等待执行器、完成、失败、取消、超时/预算耗尽。等待运行配置时可继续独立的静态审计，补充配置以新版本保存并恢复相关工作。任务运行成功与漏洞存在分别记录，解析失败不能显示为安全。软件内部智能体的职责划分属于 R01，不涉及人为成员任务分配。

优先解决影响正确性的依赖：正式软件类型和保护方式、跨架构执行、模型接口实际兼容性、RPC 版本兼容、进程取消及证据真实性。不能自动处理的对象记录能力缺口，继续适配或选择符合原类别的其他软件，不能删掉二进制要求。
