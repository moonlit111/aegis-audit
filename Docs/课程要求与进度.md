## 3. 本轮核查结果

**阶段判断：工程原型已成形，正在补关键功能和集成验证；既不是“只有方案”，也不能称为“基本通过课程验收”。** 不给没有依据的整体完成百分比，正式样本以 0/6 单独计数。

本轮合并后实测：Rust workspace 测试通过；Clippy 以 `-D warnings` 通过；rustfmt、协议生成检查、Python 35 项测试、Svelte 检查、前端格式检查和浏览器 e2e（含 `--runtime`，6 项）通过。随后复跑真实 UPX（2 项）、原生 Semgrep（1 项）、FLOSS（1 项）、UPX/FLOSS/Ghidra/IDA-D-810 智能体恢复链（1 项）和真实 DeepSeek 缺陷/修复对照；最终 DeepSeek 批次漏洞版 9/9 单元、四类 VALIDATED，修复版 9/9 单元、0 条 VALIDATED。`CVE-2016-5180` 自动利用验收生成最小输入 `\.`、两次复放和漏洞/修复对照。完整命令、范围和日志见[测试与验收方案](测试与验收方案.md)。

当前优先处理：

1. **最新基线端到端复验已完成。** 浏览器 e2e（含 `--runtime`）6 项全部通过，导入/分析连续流程和恢复面板未发现回归。
2. **智能体恢复链路已在最新基线复跑通过。** 真实 UPX、FLOSS、Ghidra、IDA/D-810 与 DeepSeek 回归均已执行。
3. **Windows FUZZ 已接入最小产品链路，并完成崩溃去重与缩减。** [RuntimeConfig](../crates/domain/src/runtime.rs)与[执行器运行分发](../crates/executor/src/runtime.rs)已支持预构建 libFuzzer 的 FUZZ；运行器按崩溃签名去重，调用 libFuzzer `-minimize_crash` 缩减，并用最小输入两次复放。`CVE-2016-5180` 已在漏洞版触发 ASan heap-buffer-overflow、修复版不崩溃，最小输入由 `a\.` 缩减为 `\.`。
4. **受限自动利用闭环已完成，正式样本仍未闭环。** `CVE-2016-5180` 已生成并归档最小崩溃输入、复现器和证据链；六项正式软件仍为 0/6。

补充定向审阅还证实动态观察、参数和单次超时存在问题：普通 stderr 关键词可被判为复现，带空格/反斜杠参数会被改写，阻塞 stdin 不受声明的单次时限约束；验证方案和实际参数类型、启动入口也有契约不一致。完整 Q01-Q09、无害复现范围及证据见[补充代码审阅](测试与验收方案.md#6-补充代码审阅)。这些问题不是要求保留 Sandbox，采用本地后端后也需正确处理。
