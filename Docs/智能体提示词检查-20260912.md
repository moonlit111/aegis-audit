# 导出确认与智能体提示词检查（2026-09-12）

阶段报告现在先显示“确认生成报告”，确认后才发送 CreateReport 请求。取消、Esc 和关闭按钮都不会生成报告；确认框展示目标、格式和当前任务状态。生成后的下载确认、请求幂等和报告历史继续生效。

检查覆盖 PLANNER、AUDITOR、REVIEWER、VERIFIER、REVERSE、REPORTER 六个后端角色，包含实际发送的系统提示词、上下文、工具返回值和结果校验。提示词版本为 `audit-15-role-contracts`，按角色拆到 [prompts](../crates/application/src/prompts)，统一入口仍是 [audit.rs](../crates/application/src/audit.rs)。

| 位置 | 问题或缺口 | 本次修正 |
| --- | --- | --- |
| 通用输出协议 | 实测复核响应套了 `type/content` 外层，历史记录也有 action 对象/工具名等协议错误。 | 明确 action 必须是 `tool` 或 `finish` 字符串，固定外层结构，禁止回显提供商字段。保留后端严格校验与有限修复。 |
| PLANNER | 规划提示词混有“在 REVERSE 角色中……”；规划职责的追加说明被发送给所有角色。 | 清理角色混用，规划只排序；已有目录和元数据不必重复查询。 |
| AUDITOR / 代码视图 | read_unit 只返回部分代码；读到末行的片段会被标为未截断，即使开头的防护未包含在内。 | 增加 unit_start_line，前后缺失都标 truncated；提示词要求补读正文并记录未读范围，不把空调用图当作无调用者证明。 |
| REVIEWER | assessments 不在主结果示例内；“有未知条件就不确定”和“有反证就拒绝”的优先顺序不清楚。 | 完整列出结果结构；先检查必要条件：有原文反证则 REJECTED，否则有未知则 INCONCLUSIVE，全部支持才 VALIDATED。保留组件范围，区分普通前提与额外攻击能力。 |
| VERIFIER | 原提示词没有完整说明模块导入先于 globals 替换、JSON 不能替代依赖，以及只读泄露无法用文件创建观察器证明。 | 对齐 Windows 适配器和观察器；明确 READY 只是配方就绪；基线和探针保持相同可信状态，不能制造无关副作用来凑验证结果。 |
| REVERSE | “四次计划调整”与后端“初始计划在内四份”不符；实测出现只看目录便称已有伪代码足够。 | 改为最多四份计划、三次修订；复用元数据只证明缓存兼容，必须阅读正文后才能评价恢复质量。 |
| REPORTER | 提示词要求总结用量和独立复核，但输入缺少测量用量、复核来源和理由，还把运行状态写死为 NOT_RUN。实测摘要误写为人工复核。 | 提供真实统计、未知用量数、复核 actor/理由、未读范围和关联运行记录；已有人工修订优先于后来的模型复核。禁止猜测人工参与，也不因未运行动态验证而贬低有原文反证的静态拒绝。 |
| 截断反馈 | max_tokens=0 表示交给提供商决定，错误却写成“预算为 0 token”。 | 准确说明提供商上限，并要求缩短重复解释、保留完整结构与证据。 |

真实接口测试使用系统已保存的 `deepseek-v4-flash-vision-exp`，推理强度为 low。调用生产的提示词拼接、DeepSeek 客户端、代码查询工具和结果校验器，输入为自包含合成样例。12 个场景覆盖：规划、带指令注释的缺陷代码、已有防护、截断正文、组件输入复核、片段外防护、未证明的全局控制能力、不可观察的只读泄露、文件写入配方、部分覆盖摘要和反编译复用。
