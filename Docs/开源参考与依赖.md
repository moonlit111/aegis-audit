# 开源参考与依赖

更新：2026-09-10。汇总仓库已有的固定版本调研，本轮核对本地清单与代码，不声称重新访问了全部上游或完成了效果对比。准确版本以 `Cargo.lock`、`frontend/pnpm-lock.yaml`、[通用工具清单](../tools/versions.json)、[Windows 工具清单](../tools/windows/versions.json)和[逆向工具清单](../tools/reverse/versions.json)为准。

## 1. 技术选择

| 已选方案 | 选择依据 | 不应推导的结论 |
| --- | --- | --- |
| Rust + Axum/Tokio | 核心任务状态、并发、证据和进程生命周期可用显式类型约束；外部分析工具仍通过进程/API 接入 | Rust 不会自动提高漏洞检出率，也不能代替目标隔离和模型输出校验 |
| Svelte + TypeScript + Vite | 从零构建单机审计工作台，静态资源由 Rust 服务提供，不引入额外 SSR 服务 | React 也是可行替代；没有本项目框架性能对比成绩 |
| Connect RPC / Protobuf | 共享业务契约，使用官方 Rust/TS 生成器，普通请求和事件流统一 | pre-1.0 依赖需要锁版本；重连补读、幂等、取消仍由应用实现 |
| SQLite + 按哈希保存产物 | 适合单机单操作员，控制服务独占写入，部署无需独立数据库 | 不宣称具备多用户共享或分布式执行平台的全部能力 |
| Python / Java 工具桥接 | 复用成熟解析、逆向、扫描和运行工具，不重写核心引擎 | 调用工具并不等于对应课程功能已经端到端验收 |

Python/FastAPI、React、REST/SSE 都能实现相同功能；当前保留既有栈，避免重写。课题允许自选技术，采用推荐栈不自动构成创新。项目只支持 Windows 宿主，不因历史 Linux 脚本仍存在而重新引入 Docker/WSL 前置要求。

Semgrep 的原生模式和忽略规则参数包含实验性接口，升级要重跑真实扫描、零目标、中文/空格路径、目标内同名模块、超时/取消和任务回传。首次被默认忽略规则跳过、深目录 socketpair 错误等失败日志仍保留，规则命中不能当漏洞确认。

JDK、MinGit、Python、Tk、Ghidra 和编译工具有各自许可。**Windows 独立包实际包含这些私有工具，不是旧 Mac 文档中的“仅附下载入口”。** 分发时保留所用发行物及其第三方声明；Python 运行时、启动器依赖和分析依赖分别收集。

历史 Linux AFL++/Sanitizer 容器实现已经从当前运行链路移除。AFL++ 采用 Apache-2.0，LLVM 按上述例外条款；历史镜像的版本/许可证以原构建记录为准。不能用旧镜像结果证明当前 Windows 宿主机已完成模糊测试。

自研工作主要在统一源码/二进制对象、不可变快照、状态/事件事务、执行器能力与租约、引文校验、多角色审计/复核、人工修订、智能体恢复计划、宿主机运行证据汇总及结构化报告。FUZZ、完整自动利用和正式软件验收仍有缺口，详见[总进度](课程要求与进度.md)。

R13 仍需实际对照说明创新性。可比较二进制覆盖、证据完整性、验证质量、检出/误报和人工辅助，但不能仅凭技术栈、功能清单或上游宣传宣称“更准确/更快”；检出和性能结论须有相同目标及可比预算的实验。

## 4. 许可收集与分发

```powershell
py -3 scripts/notices.py
py -3 scripts/package.py --standalone-windows
```

[notices.py](../scripts/notices.py) 从已安装 Cargo/pnpm 依赖读取许可元数据及原文件；[windows_package.py](../scripts/windows_package.py) 另收集 Windows Python/启动器许可并携带工具目录。运行包包含 `THIRD-PARTY-NOTICES/` 与逐文件 SHA-256 清单；Rust 清单包含可选/构建依赖，包数不等于实际加载数量。

自动生成的 notices 说明模板仍含旧的“Java/Ghidra/Git 单独安装、Linux 镜像”文字；它不改变 Windows 打包代码的实际包含内容，发布前应核对最终包与全部工具许可，不能只看模板就认定分发合规。本轮只修正文档，没有改动打包代码或生成发布包。

公开 GitHub 仓库不等于已选择项目自身的开源许可证。本轮不替用户新增项目授权条款；第三方组件继续受各自许可约束。
