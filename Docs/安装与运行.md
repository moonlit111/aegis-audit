# 安装与运行

本页对应 0.2.0 Windows 结构分析、多智能体审计与动态验证工作台。默认单机、单用户；前端静态资源由 Rust 控制服务提供，不需要独立数据库服务。结构分析不依赖模型 API，安全审计需要 DeepSeek 配置；Windows 原生隔离动态执行尚在迁移中，旧容器运行器单独说明。

当前仅支持 Windows 11 x64 宿主平台；macOS / Linux 安装路径与构建支持已移除。下文 Linux 动态运行章节只说明尚未替换的旧实现，不是 Windows-only 最终架构。新的 Windows 原生隔离执行须按[Windows 专用实施方案](Windows专用实施方案.md)完成实测后才能记为可用。面向使用者的独立 EXE 入口见[Windows 独立运行](Windows独立运行.md)。

## 环境与版本

| 项目 | 固定版本 / 前提 |
| --- | --- |
| 操作系统 | 仅 Windows 11 x64；虚拟机隔离优先使用专业版的 Windows 原生能力 |
| Python / Git | Python 3.9+、Git；用于安装、管理与 HTTPS Git 导入 |
| Windows 构建工具 | Visual Studio Build Tools，安装“使用 C++ 的桌面开发”及 Windows SDK；在 Developer PowerShell 中构建 |
| Rust | 1.98.1，含 rustfmt / clippy |
| Node / pnpm | 24.20.0 / 10.33.0 |
| Buf / Connect / Buffa | Buf 1.72.0；Connect Rust 0.9.0；Buffa 0.9.1；TypeScript 实际版本见 pnpm-lock.yaml |
| Java / Ghidra | Temurin JDK 21.0.12.1+1 / Ghidra 12.1.3 |
| Windows Semgrep | 私有 Python 3.13.13 / Semgrep 1.176.1 Windows beta；不依赖 WSL 或 Docker |
| Windows 动态执行 | 可回滚 Windows 隔离环境和原生运行器仍待实现/验收，不依赖 Mac；旧 Docker 运行器不能替代此项 |

直接依赖和传递依赖分别由 `Cargo.lock`、`frontend/pnpm-lock.yaml` 固定。大型安装包的官方 URL 和 SHA-256 记录在 [`tools/versions.json`](../tools/versions.json)。安装脚本校验下载摘要后才解压；rustup 启动器使用 Rust 官方提供的摘要，安装的 Rust 工具链版本固定。

## 从源码运行

在仓库根目录执行：

```powershell
py -3 scripts/bootstrap.py
py -3 scripts/manage.py build
py -3 scripts/manage.py doctor
py -3 scripts/manage.py start --open
```

首次安装需要下载工具链；`build` 默认构建 Release。仅开发源码路径时可使用 `bootstrap.py --core-only`，此时仍安装原生 Semgrep，但未安装 Ghidra 的二进制任务会等待具备相应能力的执行器。`build --debug` 可以加快开发构建。上述能力都不以 WSL、Docker 或开启虚拟化为前提。

工具隔离在 `.tools/`，通过 [`scripts/aegis.py`](../scripts/aegis.py) 提供 PATH、JAVA_HOME 等环境；不会改写用户全局 shell 配置。网络请求优先使用显式代理环境变量，没有设置时读取 Windows 用户的手动代理设置；PAC/WPAD 不在自动解析范围内。Git 仅继承经过校验的代理设置，仍禁用 hooks、凭据助手和全局 Git 配置，带用户名/密码的代理 URL 不会交给 Git 工具。前端、Rust 或 Buf 命令均可使用此包装器，例如：

```powershell
py -3 scripts/aegis.py cargo test --workspace
py -3 scripts/aegis.py pnpm --dir frontend dev
py -3 scripts/codegen.py --check
```

启动后访问 **http://127.0.0.1:7331**。使用“新建项目”或“导入快照”，等待导入完成，再开始结构分析。Git 入口必须提供不含凭据的 HTTPS 地址及提交/标签/分支，清单会记录最终不可变提交。导入不会执行目标仓库的构建、安装或启动脚本，也不获取递归子模块。

```powershell
py -3 scripts/manage.py status
py -3 scripts/manage.py stop
```

管理脚本只停止自己记录且进程身份仍一致的服务，先停止执行器、再停止控制服务。停止后数据保留。默认端口可通过 `start --port 7332` 指定；不同地址使用各自执行器身份目录。

## DeepSeek 官方连接

仅做结构分析时无需配置模型。安全审计已接通官方 `deepseek-v4-flash`，包括规划、审计、独立复核、验证方案及报告角色；二进制额外评估反编译质量。各角色使用独立任务和上下文，调用及实际用量持久化。

```powershell
py -3 scripts/configure_model.py
```

配置命令以隐藏输入方式接收密钥，使用当前 Windows 账户的 DPAPI 加密后原子保存到 `deepseek.token`；`model.json` 只保存模型名称。不要将密钥放进命令行参数、源码、浏览器表单或 Git 文件。旧明文配置可兼容读取，重新保存后转为 `aegis-dpapi-v1` 格式；转移账户/电脑后不能解密时应重新配置。执行器不会接收该密钥。

在“执行环境”页面点击“检测连接”，可查看实际模型、输入/输出 token、耗时及调用记录。请求有幂等标识，浏览器断线不会撤销已登记的检查。API 返回失败时保留 HTTP 状态；服务重启而未拿到结果时标为中断、用量未知。费用未根据固定单价估算，不把未知费用写为零，也不设置费用总额上限。

密钥不进入 RPC 返回值、原始调用产物或运行包；连接检测只发送固定的简短验证请求。安全审计会将所选目标的代码片段和相关证据发送到已配置的官方模型服务。模型回归与连接检测分别记录，连接成功不计入漏洞挖掘成绩。

在快照就绪后选择安全审计，查看候选发现、独立复核、关键逻辑标注及智能体任务。人工修订保存版本与历史，不能把未执行的利用改成成功。缺少动态配置时，静态证据和等待原因仍会保留。

## 旧动态运行器

以下只用于复查既有 Linux 运行证据，不属于 Windows-only 部署步骤；不会因工程检查通过而将原生 PE 动态执行标为完成。旧实现的命令为：

```powershell
py -3 scripts/manage.py runtime
py -3 scripts/manage.py doctor
```

镜像标签为 `aegis-runtime:0.2.0`，运行时固定实际镜像 ID。镜像包含 Python、Clang/Sanitizer、Semgrep 1.176.1、AFL++ 及 UPX 5.2.1；UPX 的存在不表示自动去壳已实现。基础镜像摘要与 UPX 下载摘要写在 `tools/runtime/Dockerfile`；系统包版本以实际构建镜像为准，不保证不同时间重建得到同一镜像 ID。Docker 与镜像不会由 `bootstrap.py` 自动安装。

执行器在启动时检测能力。旧 `linux-runtime`、`upx`、`afl++` 能力仍取决于遗留镜像；没有容器时它们不可用，不能算 Windows 原生动态能力。`semgrep` 现为独立的 Windows 原生静态能力，与 Docker 是否存在无关；不要为了点亮旧能力而将 Docker/WSL 设为新的安装要求。

在分析任务的运行面板加载模型已生成的验证方案，或填写所选适配器的配置。当前支持 Python 函数、单入口 C/C++ 插桩构建、原始 ELF x86_64；正常输入、重复探测、随机标记和 Sanitizer 观察均随配置归档。输入变异与 AFL++ 分别记录是否有覆盖反馈。多服务/HTTP 完整部署及原生 Windows PE 动态运行尚未实现。

每次执行使用断网容器、只读目标挂载、受限可执行临时目录和资源限制，结束或取消后确认容器回收。报告区分 `VERIFIED_COMPONENT`、`REPRODUCED`、`NOT_REPRODUCED` 与失败/取消；没有完整利用证据时，利用状态仍为 `NOT_RUN`。

## 开发模式

先停止管理脚本启动的生产服务。在三个终端分别运行：

```powershell
py -3 scripts/aegis.py target/debug/aegis-server.exe --dev-origin http://127.0.0.1:5173
py -3 scripts/aegis.py target/debug/aegis-executor.exe
py -3 scripts/aegis.py pnpm --dir frontend dev
```

Vite 将 `/api` 与 `/rpc` 代理到 7331；浏览器仍使用同源会话和 CSRF 校验。开发地址为 http://127.0.0.1:5173。结束这些前台命令可用 Ctrl+C。不要让两个控制服务同时使用同一个数据目录。

## 原生 Semgrep

安装和任务执行均使用 `.tools/windows-python/python.exe` 及固定发行包的控制台模块入口，不依赖系统 Python 或 pip 生成的绝对路径 EXE。顶层 `python -m semgrep` 不是该版本的有效入口。规则使用本地文件，关闭 metrics 与版本检查，不执行目标代码，也不调用模型。

Semgrep 在安全审计的源码准备阶段执行；未安装、扫描非零退出或输出不合法时保留原因及结构信息，工具启动/进程回收异常则让工作项失败，不伪装成功。扫描 JSON 按快照路径及文件字节范围校验，并列出未扫描源码。`NO_TARGETS`、`PARTIAL`、`FAILED` 不等同于“没有漏洞”。Beta CLI 和实验性参数必须通过下述真实工具回归后才可升级，详细限制见[原生工具调研](Windows原生工具调研.md)。

## Ghidra 平台细节

- Windows 便携包已在中文与空格的 SDK 路径上完成 PE32/PE64/ELF 真实分析。安装脚本保留用户自己的 SDK 缓存，不再因为中文用户名而转移到共享的 Public 目录；位置记在 `.tools/paths.json`，可用 `--sdk-dir` 指定。Windows 批处理入口仍拒绝 `%!&|<>^` 等 shell 特殊字符路径。
- Ghidra 项目目录不能包含点号开头的路径段。执行器在系统临时目录建立独立项目，不把 Ghidra 项目放在 `.data/`。
- 只使用发行包的 `win_x86_64/decompile.exe`，不再编译或选择 Mac / Linux 原生组件。组件缺失时安装失败，不回退到其他平台。
- 启动检查同时核对 Java、Ghidra 版本、Windows 原生反编译器和导出脚本；不能仅凭文件存在宣称可分析。
- Ghidra 可能在后处理脚本失败时仍退出 0。执行器还要求存在合法结果产物，并校验文件、函数、位置和覆盖记录。

## 数据、资源与恢复

| 路径 / 限制 | 含义 |
| --- | --- |
| `.data/server/aegis.sqlite` | SQLite WAL 数据库；项目、快照、任务、事件与产物索引 |
| `.data/server/blobs/` | 以 SHA-256 寻址的原始和生成产物 |
| `.data/server/*.token` | 本地会话及执行器引导凭据，不要提交或随运行包分发 |
| `.data/executor*/identity.json` | 绑定控制服务地址的执行器身份 |
| `.data/executor*/active.json` | 当前任务及尚待重报的结束结果 |
| `.data/logs/` | 管理脚本启动的服务日志 |
| `.data/verification/` | 独立回归的数据目录、原始调用、执行记录与报告 |
| `.data/handoff/` | Windows 源码交接 ZIP 及 SHA-256；不含本地模型配置与运行数据 |
| ZIP / 文件上传 | 512 MiB；ZIP 解压总量 512 MiB、单文件 32 MiB、20,000 个条目 |
| 浏览器文件夹打包 | 128 MiB、20,000 个文件，随后走相同 ZIP 导入流程 |
| 源码解析 | Python / Go / C / C++；有效 UTF-8；单文件 2 MiB、语法解析时限 1 秒 |
| 二进制分析 | PE x86/x64、ELF x86_64；最多 5,000 个函数，保留失败和截断记录 |
| 工具执行 | 单工作项整体时限 300 秒；Git 单步骤 120 秒；Ghidra 自动分析单文件 120 秒；Ghidra 最大堆 2 GiB |
| 结果 / 日志 | 结果 JSON 最大 64 MiB；stdout、stderr 各保留最多 4 MiB，截断有标记 |

ZIP 路径穿越、符号链接、大小写/Unicode 归一化冲突与 Windows 保留文件名会被拒绝。源码快照排除 `.git`、常见依赖/构建目录及本地 `.env` 文件，原因保留在清单中。原始上传产物仍归档；浏览器文件夹和自行准备的 ZIP 应只包含本次分析目标。

浏览器断开连接只停止订阅，不取消工作。重新进入任务页面从已持久化事件恢复；显式取消会等待工具进程回收确认。执行器心跳失效后，旧结果被隔离，不会自动重复执行未知进程状态的任务。重启执行器时，已保存且确认回收的结束结果可以幂等重报；如果旧任务没有回收确认，执行器会停止领取新任务，应先核实旧进程状态。

工具管理提供 Windows Job Object、环境变量白名单、独立临时目录、超时、取消与产物访问范围。工具临时文件不写入目标源码目录，避免扫描自身临时产物及 Windows 原生 socket 的深路径限制。正式 Windows 历史漏洞软件仍需可回滚的独立执行环境，进程树回收本身不能代替目标隔离。

数据库和 blobs 应一起备份。建议先正常停止服务，再复制整个 `.data/server/`；只复制 SQLite 主文件而遗漏正在使用的 WAL 可能丢失最新记录。

## 检查与运行包

```powershell
py -3 scripts/manage.py check
$env:AEGIS_NATIVE_SAST_EVIDENCE = Join-Path $PWD '.data/verification/native-sast'
py -3 scripts/aegis.py cargo test --workspace --locked native_ -- --ignored --test-threads=1
py -3 scripts/aegis.py pnpm --dir frontend exec playwright install chromium
py -3 scripts/e2e.py
py -3 scripts/check_audit.py --live-model
py -3 scripts/package.py --standalone-windows
py -3 scripts/prepare_windows.py
```

`e2e.py` 在独立临时数据目录启动真实控制服务和执行器，结束后回收进程，测试结果写入 `.data/verification/`。`--skip-ghidra` 只用于明确缺少 Ghidra 的环境，会跳过二进制浏览器用例，不能计为二进制验证通过。正常完整检查不要传此选项。

模型回归使用 `target/debug` 程序，先运行 `py -3 scripts/manage.py build --debug`。`check_audit.py --live-model` 使用已配置的官方 API 并产生实际用量。原生工具回归不调用模型；需要先完成 bootstrap，因此单独显式运行，Windows CI 也包含该步骤。历史 `check_runtime.py` 和 `e2e.py --runtime` 使用 Linux 容器，不是当前 Windows 原生验收。历史证据见[审计与动态验证交付记录](审计与动态验证交付记录.md)。

`package.py` 仅输出 Windows x64 的 ZIP、SHA-256、逐文件清单和依赖许可证；不会包含 `.data/`、密钥或分析目标。默认的精简包不含 `.tools/`；`--standalone-windows` 会包含指定的私有运行组件，但不会把整个开发工具目录打包，也不交叉生成其他平台可执行文件。

完整便携包从 `AegisAudit.exe` 启动，无需另装 Python、Git、Java、Node 或 Rust，具体约定及尚未完成的验收见[Windows 独立运行](Windows独立运行.md)。精简包需要 Git 与 Python，然后运行 `py -3 scripts/bootstrap.py --runtime-only` 安装私有 Python/Semgrep、Java/Ghidra，再用 `py -3 scripts/manage.py start --open` 启动。两种包的静态功能都不需要 Docker/WSL；安全审计在新环境中需自行配置模型。数据库迁移嵌入 Rust 服务，首次启动或升级时自动执行；升级前按上文备份数据。

`prepare_windows.py` 生成当前工作区的源码 ZIP，包含尚未提交的开发变更，并附逐文件清单和整包 SHA-256。它与当前平台的可执行运行包分别生成，Windows 需要从源码原生构建。Windows 接力使用方式及预检查命令见[Windows 接力任务](Windows接力任务.md)。Win11 专业版本机及独立部署验收应按实际结果登记，不能用 Mac 静态解析 Windows PE 的结果代替。
