# 安装与运行

当前支持 **Windows 11 x64**。主服务、界面、导入、静态分析、智能体恢复和宿主机 VERIFY 均无需 WSL、Docker 或 Sandbox；模型审计需要已配置的 DeepSeek 或 OpenAI 兼容聊天接口，纯结构分析不需要模型。启动成功不代表课程验收已完成，见[课程要求与进度](课程要求与进度.md)。

## 从源码运行

前提：Python 3.9+、Git、Visual Studio 的 C++ 桌面开发工具及 Windows SDK。在 Developer PowerShell 中进入仓库：

```powershell
py -3 scripts/bootstrap.py
py -3 scripts/manage.py build
py -3 scripts/manage.py doctor
py -3 scripts/manage.py start --open
```

默认 http://127.0.0.1:7331。`build` 默认产出 Release；`build --debug` 供开发测试，但 `manage.py start` 优先选择已有 Release，不要将旧程序的结果当成新源码测试。

```powershell
py -3 scripts/manage.py status
py -3 scripts/manage.py stop
```

`start --port 7332` 可避开端口占用，但**不会自动隔离服务数据库**，不要用它同时启动两个写入同一 `.data/server` 的测试实例。独立回归优先使用 `scripts/e2e.py` 等自带临时服务/数据目录的脚本。不要停止其他会话正在使用的服务。

### 前端开发服务

开发调试可单独启动 Vite：

```powershell
cd frontend
corepack pnpm install
corepack pnpm dev
```

默认地址为 http://127.0.0.1:5173/。Vite 会把 `/api` 与 `/rpc` 代理到 http://127.0.0.1:7331，因此仍需先用 `py -3 scripts/manage.py start` 启动控制服务与执行器；只启动 Vite 时页面会提示无法建立本机会话。

## 模型配置

在网页“执行环境”中点击“配置模型连接”或“编辑模型连接”，填写接口类型、API 基础地址、模型标识和密钥后保存。保存本身不调用模型；“检测连接”会发起真实请求并记录服务商返回的用量。安全审计会将当前目标的代码片段和相关证据发送到选定的模型服务。

DeepSeek 官方模式固定使用 `https://api.deepseek.com`。自建或其他供应商选择 OpenAI 兼容接口，地址填写到基础路径，例如 `https://example.com/v1`；程序追加 `/chat/completions`。远程地址须使用 HTTPS，本机回环地址可使用 HTTP。地址不能包含用户名、密码、查询参数或片段。兼容模式在连接检测和实际审计中均发送 `response_format: {"type":"json_object"}`，所选接口和模型须支持这一标准 JSON 输出参数；不发送 DeepSeek 专用思考参数，界面中的思考强度不会映射为其他供应商的专用参数。接口拒绝参数时会记录失败，不会静默降级或额外发起未计入预算的请求。

网页配置在 SQLite 中以事务保存，密钥使用当前 Windows 用户的 DPAPI 加密；页面不会回显已存密钥。已有审计（包括排队、等待执行器及取消中）或连接检测期间不能修改配置。更换接口地址或类型时，须重新填写该接口的密钥，或移除保存的密钥，避免将旧接口凭据发送到新地址。其他窗口修改过配置时，需重新打开编辑器读取最新版本。

也可通过隐藏输入配置官方 DeepSeek 接口：

```powershell
py -3 scripts/configure_model.py
```

初始化后的服务与命令行/便携版托盘使用同一份 SQLite 配置。首次启动前，命令行仍写入兼容的 `model.json` 和加密 `deepseek.token`；没有网页配置时服务会读取这些文件。跨 Windows 账户或机器不能解密时重新配置。不要将密钥放在命令行参数、源码、浏览器 localStorage 或日志中。执行器不接收模型密钥。

服务端环境变量可作为回退配置：

| 变量 | 用途与优先级 |
| --- | --- |
| `AEGIS_MODEL_ENDPOINT` | 本地未指定基础地址时使用；默认官方 DeepSeek 地址 |
| `AEGIS_MODEL` | 本地未指定模型时使用；默认 `deepseek-v4-flash` |
| `AEGIS_MODEL_API_KEY` | 没有保存密钥时使用，仅绑定 `AEGIS_MODEL_ENDPOINT` 指定的地址；未指定地址时绑定官方地址 |
| `DEEPSEEK_API_KEY` | 官方 DeepSeek 模式下的最后密钥回退，不用于其他地址 |

网页会显示实际凭据来源。移除保存的密钥后，匹配地址的环境变量仍可生效；该操作不会删除环境变量。更改服务进程的环境变量需重启服务。连接检测仅验证接入，不代表模型审计效果已验收。

## 报告与 PDF

任务页面可导出 JSON、HTML、Markdown 或 PDF。运行中也能导出阶段报告；报告历史记录数据截至时间、导出时任务状态和报告类型，后续复核或标注变更不会改写已导出的文件。

PDF 使用本机 Edge 或 Chrome 进行离线排版，可通过 `AEGIS_PDF_BROWSER` 指定浏览器可执行文件。程序为每次排版建立独立临时配置，不使用操作员浏览器资料；未安装可用浏览器时，页面会给出明确错误，其余报告格式仍可用。

## 便携包

完整解压运行包，双击 `AegisAudit.exe`。入口内置启动运行时，并随目录提供服务、执行器、前端及指定私有工具；不是只复制一个 EXE。普通使用者无需安装 Rust、Node、Java、Git 或开发工具。

托盘提供打开应用、模型配置、日志和退出。关闭浏览器不会停止任务；退出托盘才停止本次拥有的服务/执行器。不同目录是不同安装实例；重复启动、端口冲突和进程恢复由启动器处理。

```powershell
.\AegisAudit.exe --stop
.\AegisAudit.exe --diagnostics .\doctor.json --non-interactive
.\AegisAudit.exe --configure-model
```

构建与校验入口：

```powershell
py -3 scripts/package.py --standalone-windows
py -3 scripts/check_windows_package.py <本次ZIP路径> --output <不存在的验证目录>
py -3 scripts/prepare_windows.py
```

最后一个命令导出当前源码，包括未忽略的未提交改动，排除本机数据和密钥；解压后修改前可用 `py -3 scripts/prepare_windows.py --verify` 检查清单。运行包与源码包分别管理；新 ZIP 必须使用自己的哈希及验收结果，不能沿用旧包成绩。当前发布物未签名，早期本机重定位测试不等于最新包或干净系统验收。

## 逆向工具与动态验证

固定版 UPX 与 FLOSS 由 bootstrap 安装；IDA / Hex-Rays 属于本机商业软件，需要自行安装后再探测：

```powershell
py -3 scripts/install_reverse_tools.py
py -3 scripts/configure_d810.py --ida-dir '<IDA 安装目录>'
py -3 scripts/manage.py runtime
py -3 scripts/manage.py doctor
```

`runtime` 准备 UPX 与 Zig；`doctor` 输出各工具真实探测结果。D-810 依赖需按[逆向交接](智能体逆向与解混淆交接.md)单独安装。工具存在不等于正式闭源软件验收通过。

当前 VERIFY 由 Windows 宿主机运行器执行，FUZZ 仍未接入产品。历史 Linux 容器与 TinyInst/libFuzzer 实验不能当作当前产品能力；不要为了旧回归重新安装 Docker/WSL。

## 宿主机运行边界

**可以不依赖 Sandbox 做该课题，老师没有规定必须用沙箱；当前产品已采用宿主机执行。** 需要分清三种情况：

| 工作 | 能否直接在宿主运行 |
| --- | --- |
| 控制服务/前端、导入、Tree-sitter、Ghidra、Semgrep、UPX 静态解包、模型审计/报告 | 已经直接运行，不启动被分析目标，不需要 Sandbox |
| 人工确认过的自写正常程序或可控测试夹具 | 可由宿主机 VERIFY 运行器执行；仍需固定输入、超时和回收 |
| 不熟悉的旧闭源程序、模型生成验证脚本、漏洞触发输入、安装器/服务/驱动 | 即使不是恶意软件，也可能误写文件、启动子进程、修改系统或耗尽资源；本地执行前需明确这些副作用和恢复办法 |

“不分析恶意软件”能缩小风险范围，但不能保证漏洞触发、构建脚本或生成的 PoC 没有副作用。工作目录和环境白名单也不能阻止同一用户身份读取其他文件；Job Object 不是文件/网络隔离。

服务端要求 `windows-host` 能力，执行器使用 Job Object、独立临时目录和环境白名单执行目标。结果必须记录 `WINDOWS_HOST`，不能伪装成沙箱、容器或断网证明。

本地后端仍应使用普通权限、独立临时目录、固定目标/输入哈希、环境白名单、Job Object 资源限制/超时/取消，记录正常输入与重复验证。结果必须标明实际本地执行环境，不能伪造沙箱会话或断网证明，也不应因省略 Sandbox 而默认以管理员身份运行。这些是运行正确性和可追溯性要求，不是要求重新引入沙箱。

执行前确认目标架构、入口、输入和预期副作用；不要以管理员身份运行为了省事。完整端到端浏览器流程和正式软件验收仍需按[课程要求与进度](课程要求与进度.md)复跑。

## 数据与排错

| 路径 / 情况 | 处理 |
| --- | --- |
| `.data/server/aegis.sqlite`、`blobs/` | 数据库和证据一起备份；先正常停止服务，避免漏掉 WAL |
| `.data/server/*.token` | 本机凭据，不提交、不展示、不打包分发 |
| `.data/executor*/active.json` | 活动任务/回收记录；先确认进程和会话状态，不直接删除以绕过恢复 |
| `.data/logs/`、`.data/verification/` | 应用日志与独立测试证据 |
| `doctor` 退出 0 | 仍需逐项查看工具能力，不代表全部功能可用 |
| 执行器停止领取任务 | 先查看 `active.json` 和进程回收状态，不删除记录绕过恢复；必要时按最新基线复跑 e2e |
| 升级 / 分发 | 退出后备份数据；分发原始构建 ZIP，不重新压缩带有凭据的已使用目录 |

开发与验证命令集中见[测试与验收方案](测试与验收方案.md)。
