本项目选定课程设计第 1 题：**基于大模型智能体的软件漏洞挖掘系统设计与实现**。

项目采用“以需求驱动设计、用已有漏洞检验能力”的方向。系统面向未专项适配过的源码和二进制开展漏洞挖掘；公开历史漏洞提供评测依据。系统主体自行实现，可以充分借鉴开源设计与模块源码，并记录来源及改动。

**项目的设计、实现、调试、测试和技术文档由 Codex 承担。** 开发计划只保留依赖、执行顺序及完成标准，不制定日历排期或成员开发分配。课程规定的提交信息按真实情况整理。

| 文档 | 用途 |
| --- | --- |
| [具体实现方案](具体实现方案.md) | 编码依据：工程结构、数据与状态、智能体、分析工具、RPC、界面及验收对应 |
| [项目方案](选题一可行性分析与初步方案.md) | 已确定的定位、需求编号、技术路线、能力边界与自研内容 |
| [开发实施计划](开发实施计划.md) | 按依赖推进的实现顺序、完成标准和环境准备 |
| [测试与验收方案](测试与验收方案.md) | 历史漏洞检验、独立测试集、修复对照、正式样本和评测指标 |
| [技术栈对比与建议](技术栈对比与建议.md) | Rust/Python、Svelte/React、Connect RPC/REST+SSE 的比较及取舍 |

已确定采用 **Rust + Axum/Tokio 核心后端、TypeScript + Svelte 前端、Connect RPC 通信、SQLite 存储**。Python/Java 保留用于必要的分析工具适配脚本。技术栈已选定，尚未开始应用实现；具体版本和互通能力在实际验证后固定。

执行环境为 Windows 主执行和最终验收，Mac 用于日常开发与平台调试。Windows 电脑由用户确认配置为 Intel Core i9-13900HX、32 GB 内存、500 GB 硬盘；Mac 经本地检查为 ARM、16 GB 内存。Windows 的系统版本、虚拟化及工具状态尚待实际检查。

模型候选为 deepseek-v4-flash 或 glm-5.3 的 API，服务地址、模型标识和密钥通过配置提供。一个模型可承担多个独立上下文的智能体角色。

已完成需求复核、技术栈选择、具体工程设计、技术资料核查和本地环境只读检查。[具体实现方案](具体实现方案.md)已补齐，可作为下一步编码依据。尚未创建应用代码、安装项目依赖、连接 Windows 执行机或执行漏洞测试。课程规定的六个正式软件测试条目尚未全部落实，候选案例不计为通过。

R01—R15 对应课程要求，U01—U06 对应本次确定的项目约束。实现与测试按编号提供证据，开发中的阶段成果不减少最终验收范围。
