本项目选定课程设计第 1 题：**基于大模型智能体的软件漏洞挖掘系统设计与实现**。

项目采用“以需求驱动设计、用已有漏洞检验能力”的方向。系统面向未专项适配过的源码和二进制开展漏洞挖掘；公开历史漏洞提供评测依据。系统主体自行实现，可以充分借鉴开源设计与模块源码，并记录来源及改动。

**动态验证按当前项目约定直接在 Windows 宿主机执行，不再维护独立沙箱后端。** 详细任务、文件所有权、依赖与验收门槛见[后续执行与三人分工](后续执行与三人分工.md)。贡献与 AI 协助按实际情况整理。

已确定采用 **Rust + Axum/Tokio 核心后端、TypeScript + Svelte 前端、Connect RPC 通信、SQLite 存储**。Python/Java 保留用于必要的分析工具适配脚本。当前 0.2.0 在结构分析工作台上加入多智能体审计、独立复核、人工修订和 Linux 动态执行；具体能力和实际验证范围见[审计与动态验证交付记录](审计与动态验证交付记录.md)。

首版漏洞挖掘范围已确定为注入、路径遍历、认证/授权缺陷和内存越界，四类开发夹具的真实模型审计及动态缺陷/修复对照已通过。已对照课程 PDF 确认原文未限定漏洞类型；完整功能和三类软件各两种的正式测试要求仍按原文执行，开发夹具不计入六项正式软件。

当前只支持 Windows 11 x64 开发、构建、部署和最终验收，不再维持 Mac 或 Linux 宿主平台。实机已核查为 Windows 11 Pro build 26200、Intel Core i9-13900HX、31.7 GiB 内存；原生构建、源码与 PE32/PE64/ELF 静态分析已经本机运行。动态验证使用宿主机运行器和 Windows Job Object 进程回收，不要求虚拟化或独立沙箱。Windows-only 完整目标、当前证据和剩余工作见[Windows 专用实施方案](Windows专用实施方案.md)。历史 Mac 日志保留为来源记录，不计入 Windows 实机成绩。

模型服务已确定使用 DeepSeek 官方 API，首版按此前偏好优先适配 deepseek-v4-flash。服务地址、模型标识和密钥引用通过配置提供，一个模型可承担多个独立上下文的智能体角色。用户不设 API 费用总额上限。历史平台已完成真实模型审计与修复对照；Windows 本机的真实连接检测已通过，真实审计及修复对照仍需单独回归，不能沿用历史平台成绩。

当前 Windows 工程日志包括 36 项常规 Rust 测试、18 项 Python 测试和另行启用的 4 项真实 Windows 工具测试。安装方式见[安装与运行](安装与运行.md)，准确边界见[Windows 实机验证记录](Windows实机验证记录.md)。自动保护处理、完整目标利用和实际开源对照仍待完成，六项正式软件仍为 0/6。
