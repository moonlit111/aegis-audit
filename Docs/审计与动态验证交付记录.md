# 审计与动态验证交付记录

版本：0.2.0。日期：2026-09-09。本轮在 0.1.0 程序结构工作台上接入通用审计、独立复核、人工修订和 Linux 动态执行，并完成开发夹具的缺陷/修复对照。正式课程样本仍为 **0/6**。

## 当前能力

| 模块 | 已实现行为 |
| --- | --- |
| 多智能体 | PLANNER、AUDITOR、REVIEWER、VERIFIER、REPORTER；二进制额外使用 REVERSE 评估反编译质量。任务、调用、用量、预算、中断及重试持久化；复核使用独立原始代码上下文 |
| 审计与规则 | 当前目标范围内的代码、行范围、文本、调用关系查询；Semgrep 容器扫描与内建线索；四类缺陷的通用语义审计，不按项目名或 CVE 判断 |
| 引文与范围 | 模型选择程序单元及行号，服务从原始代码生成引文；越界位置、外部单元和显式伪造引文被拒绝。函数体按任务分开审计，同类发现按源码位置去重 |
| 独立复核 | 分别记录输入控制、操作可达性、防护缺口及额外攻击前提；未知的必要前提不能判为成立。组件级静态结论与完整部署、动态执行结论分别显示 |
| 人工修订 | 漏洞复核、认证/加解密/注册标注、版本冲突检测和修订历史；人工备注不能写入动态验证成功 |
| 运行验证 | 独立、可取消的运行任务；Python 函数、单入口 C/C++ 插桩构建、原始 ELF x86_64；正常输入、重复测试、随机标记、文件观察和 Sanitizer 诊断 |
| 模糊测试 | 输入变异与 AFL++；区分是否有覆盖反馈，保存执行数、异常输入、输入缩减和两次复测记录 |
| 隔离与证据 | 固定 Linux amd64 镜像 ID、断网、只读目标、独立可执行临时目录、资源限制、容器回收；目标、配置、镜像、测试脚本、原始观察及工具日志相互关联 |
| 界面与报告 | 漏洞/复核/智能体/运行面板、方案执行与配置补充、事件回放；JSON/HTML/Markdown 导出包含实际运行记录，未执行的利用保持 NOT_RUN |

结构化输出允许无关的描述元数据和可选限制列表；必需的业务字段、证据位置和执行约束仍逐项检查。错误保留为原始调用记录，最多进行两次格式纠正；纠正阶段关闭模型思考输出以稳定 JSON。失败的验证方案不会丢弃此前静态证据，未完成任务仍使整体结果保持 PARTIAL。

## 复验

```bash
python3 scripts/manage.py build --debug
python3 scripts/manage.py runtime
python3 scripts/manage.py check
python3 scripts/check_audit.py --live-model
python3 scripts/check_runtime.py
python3 scripts/e2e.py --runtime
```

模型回归使用已配置的官方 API；动态回归和浏览器回归不需要模型密钥。每次检查使用独立服务、执行器和数据目录。本页早期 Linux 容器记录仅作历史来源，不计为当前 Windows 宿主机运行结果。

本地工作台已在 **http://127.0.0.1:7331** 运行 0.2.0。运行包位于 `.data/dist/`，Windows 源码交接包位于 `.data/handoff/`；这些本机产物和升级备份不提交到 Git。源码提交推送后，Windows 会话可按交付提交号获取，或校验、解压源码 ZIP，具体步骤见[Windows 接力任务](Windows接力任务.md)。
