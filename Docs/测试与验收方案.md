运行验证判定为 `REPRODUCED` 时，服务直接产出可复用的利用证据包，不需要人工整理：证据 JSON、复现配方和复放脚本各一份，并把关联发现的状态从 `VALIDATED` 推进为 `REPRODUCED`。

## 5. 验收方法

### 输入与答案隔离

产品侧只接收目标代码/二进制、正常构建与启动方法、输入接口、范围和预算；评测侧保存 CVE、参考 PoC、补丁、预期位置和影响。`evaluation/reference`、修复答案、其他任务、密钥及开发文档不能进入分析目录或模型工具权限范围。

先冻结模型/提示词、目标与工具版本、预算、种子及人工辅助范围，再进行挖掘；最后对照答案。公开 CVE 可能已存在于模型训练数据中，盲测不能证明模型从未见过。开发用过的案例不能再称未见保留集。

### 功能与结果

| 验收组 | 必须保留的事实 |
| --- | --- |
| R01-R06 | 多角色任务交接、真实位置/地址、源码和伪代码审计、保护识别与工具执行、恢复前后映射、调用/控制流依据及认证/加解密/注册标定 |
| R07-R10 | 真实输入生成/变异和执行数、覆盖反馈是否存在、崩溃输入与复测；独立复核的反证/不确定；系统生成的验证或利用产物、目标影响和完整证据链 |
| R11-R12 | 人工修订冲突与历史，刷新/断线补读，取消/超时/清理失败，导出内容与数据库和原始产物一致 |
| R13-R15 | 同一版本和可比预算的开源系统对照，六项资格与挖掘/利用逐条完成，干净 Windows 部署及课程提交材料 |

每个正式案例记录中性编号、开发/正式/保留用途、来源/许可、提交/版本、SHA-256、保护证据、正常运行条件、模型/工具版本、实际用量、全部重试、候选/复核、执行产物、失败和人工辅助。缺正常运行条件时允许补充、版本化和复用；不能要求用户提供漏洞位置或参考 PoC 再声称自主发现。

四类首版缺陷分别为注入、路径遍历、认证/授权和内存越界。需有缺陷版、修复版及正常对照，但不额外要求每个正式软件都同时包含四类漏洞；简单历史案例为主，包含 1-2 个较复杂案例。更换项目不得靠新增项目名/CVE 专用检测分支通过。

“候选”“静态复核成立”“组件验证”“异常复现”“完整利用成功”分别统计。退出码、打印成功或单次崩溃都不足以证明完整利用；未复现不直接判误报，无法解析/运行不判安全。未知结论不混入已确认真阳性；只有标注充分才计算召回率，所有指标保留原始数量和分母。

开源对照优先评估 DeepAudit，并区分静态工具、单智能体和完整系统。仅比较双方适用的任务，功能差异与检出/性能成绩分开写。当前 Windows-only 约束不因对照工具使用 Linux 而自动取消；需要环境例外时另行确认，不能只跑 Semgrep 就宣称完成整套开源系统对照。

最终版本、运行包哈希、报告、PPT 与录像必须一致。清除 PATH 或本机重定位有价值，但不等于干净操作系统验收；最终交付项及分工对应见[总进度](课程要求与进度.md)。
