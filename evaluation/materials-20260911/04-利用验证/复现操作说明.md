## 1. 一键复现

任选其一：

```bat
:: 方式 A：直接跑编排脚本（推荐，输出最干净）
.venv\Scripts\python.exe -X utf8 run_all.py

:: 方式 B：双击 run_all.cmd（命令行也行），效果相同、跑完等你按键
run_all.cmd
```

编排脚本 `run_all.py` 会依次执行 p01 → p03 → Go 四目标，逐步打印输出，最后给出"全部步骤完成"。
（`run_all.cmd` 是纯 ASCII 包装——批处理文件的解析受代码页影响，中文全放在 Python 里避免编码坑。）

## 3. 每个 PoC 看什么

### ① p01 · Jinja2 模板注入（预期总耗时 <5 秒）

**预期输出**：
```
== vuln 版本（sha256 be766d347e89bbad…）
[结果] vuln: 渲染成功，模板代码被执行
[结果] marker 内容(whoami): '你机器的用户名'
== fixed 版本（sha256 f0e12c53e137acbf…）
[结果] fixed: 抛异常 SecurityError: access to attribute '__class__' of 'tuple' object is unsafe.
[判定] 漏洞版执行了模板代码并写出 marker；修复版被沙箱拒绝、未生成 marker。
```

**手动复看点**：
- `poc1-jinja模板注入/evidence/jinja_poc_marker_from_vuln.txt` —— 里面是**漏洞版渲染时执行的主机命令输出**（`whoami` 的结果），代码执行的最硬证据。
- `poc1-jinja模板注入/evidence/blocked_fixed.txt` —— 修复版被沙箱拦下的原话。
- 想自己改载荷：编辑 `run_poc.py` 顶部的 `PAYLOAD`（Jinja 模板串），换命令/换动作都行，改完重跑。
- 原理备注：漏洞版 `realpath` 那种"原样代码"在 `../01-源码对照/p01-llama-jinja/`；脚本会打印所用文件的 sha256，核对两版文件即可。

### ② p03 · XSS（预期总耗时 <15 秒，Chrome 启动几次）

**预期输出**（矩阵）：
```
== vuln 版本
  A 用户消息输出: <pre ...><img src=x onerror="document.title='XSS-USER'"></pre>
  user 页面浏览器标题: 'XSS-USER' -> 脚本已执行(注入成功)
  assistant 页面浏览器标题: 'XSS-ASSISTANT' -> 脚本已执行(注入成功)
  C 非字符串消息: 抛 TypeError: ...
== fixed 版本
  A 用户消息输出: <pre ...><img src="x"></pre>
  user 页面浏览器标题: 'BEFORE' -> 未执行(被拦截/无注入)
  assistant 页面浏览器标题: 'XSS-ASSISTANT' -> 脚本已执行(注入成功)
  C 非字符串消息: 抛 TypeError: ...
```

**手动复看点（这个最直观，建议亲眼看）**：
- 直接双击打开 `poc2-xss消息注入/evidence/` 下的四个 html：
  - `vuln_user.html` / `vuln_assistant.html` → 打开后**标签页标题会变成 XSS-USER / XSS-ASSISTANT**（脚本被执行）；
  - `fixed_user.html` → 标题保持"BEFORE"（被 nh3.clean 拦住）；
  - `fixed_assistant.html` → **标题仍会被改写**（"上游修复不完整"的直观证明）。
- 注意：Windows 上双击 html 会在默认浏览器打开，效果一致。
- 想换载荷：编辑 `run_poc.py` 顶部的 `USER_PAYLOAD` / `ASSISTANT_PAYLOAD`。

### ③ p06/p07/p08/p09 · Go 四目标（预期总耗时 <1 分钟）

跑完看 `poc3-go复现/结论.txt`，四个要点：

| 目标 | 看哪行 | 预期 |
| --- | --- | --- |
| p06 | `POC_RESULT=PANIC  runtime error: index out of range [0] with length 0`（vuln） / `POC_RESULT=NO_PANIC`（fixed） | 漏洞版越界 panic、修复版正常 |
| p06 完整栈 | `poc3-go复现/p06-parts-panic/evidence/vuln-panic-raw.txt` | 栈里直接指出 **`server/download.go:175`** |
| p07 | vuln：`判定: 相对路径越出 Modelfile 目录、按进程 CWD 解析并读取成功`；fixed：三段里 A/B 也是"读取成功"、C 才被约束 | 漏洞成立 + 修复不彻底 |
| p08 | `[极端] length=math.MaxInt64 -> panic: makeslice: len out of range` | 缺上界校验（但代码里无攻击者可控入口，见 `main.go` 顶部说明） |
| p09 | `WARNING: DATA RACE`（vuln 和 fixed 都有） | 数据竞争，race detector 输出里可见 `maphash` ← `hashImage`（image.go:140）← `NewEmbed`（image.go:71） |

**手动复看点**：
- 想看 race 报告全文：`poc3-go复现/p09-race/evidence/vuln-output.txt`（搜 `WARNING: DATA RACE`，下方有 Read/Write 的精确行号）。
- 想单独跑某个目标：进 `poc3-go复现/<目标>/vuln`（或 `fixed`），直接 `go test -v ./server/ -run TestPrepareMissingContentLength`／`go run .` 等（Go 在 `D:\kechngsheji\tools\go\bin`）。
- 想改触发条件：p06 的触发是"HEAD 响应没有 Content-Length"（`p06-parts-panic/*/server/stubs.go` 的 `makeRequestWithRetry` 返回的固定响应）；给它加上 `Content-Length` 头就不再触发。

## 4. 常见问题

| 现象 | 处理 |
| --- | --- |
| 控制台中文乱码 | 用 `run_all.cmd`（内部已 `chcp 65001`）；或先执行 `chcp 65001` |
| `ModuleNotFoundError` | 用的是系统 Python；必须用 `.venv\Scripts\python.exe` |
| PoC2 报"浏览器执行失败" | Chrome 路径不对，改 `poc2-xss消息注入/run_poc.py` 顶部 `CHROME` 常量 |
| PoC3 报"Go 工具链不存在" | 改 `poc3-go复现/run_all.py` 顶部 `GO` 常量，或装 Go 后指过去 |
| 移动了整个材料目录 | 只要保持 `01-源码对照/` 与 `04-利用验证/` 的相对位置不变，脚本无需改动（Go/Chrome 路径除外） |
